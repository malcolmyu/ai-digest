● 观点解析 02 / 03
为什么这套 Skills 和别的不一样
🔧单一职责，不是万能助手
每个 skill 只做一件事。diagnose 只负责调试流程，tdd 只负责红绿重构，grill-me 只负责追问你的计划。没有「全能助手」那种几十页的泛化技能文档。
"这是技能。其他一切都是机械的。" — diagnose/SKILL.md
📐建立工程纪律，而非教写代码
grill-with-docs 逼你在写代码前先把领域语言对齐。zoom-out 在越陷越深时拉你回战略层。triage 逼你先分类再动手。技能 = 工作纪律 × 单一场景。
● 灵魂拷问 03 / 03
Skill 越来越多，Agent 会不会变成技能缝合怪？
● 答案
不会——核心设计是「按需加载」。Matt 把这 28 个 skill 放在 6 个 bucket 里，diagnose 只在调试时触发，to-prd 只在写需求时触发。你不需要同时加载全部——Agent 按当前 task 的语义自动选择。

更关键的是：SKILL.md 是渐进式加载——skill_view() 第一次只看名字+描述，第二次才展开完整内容。100+ skills 共存而不炸 token 预算。
