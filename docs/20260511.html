● 释义 02 / 07
"自闭天才"到底指什么
🧠聪明，但不按常理出牌
极其聪明是这个描述的前半句——能力上有真实飞跃。
后半句是"不按常规来"：它解决问题的方式、回复模式、甚至代码风格，都跟自己之前的不一样。不是 bug，是特征。
"它做对的方式跟你想的不一样，但结果就是更好。" — Sam Altman
🏷️代号 5.5 本身就是信号
跳过了 4.0 → 5.0 的常规命名，直接叫 "5.5"。
Altman 承认这个命名"很奇怪"——但他说得坦然。
本质是：版本号已经不重要了。能力的跳跃不再是整数级的。

● 反驳 04 / 07
Dan Shipper 泼了盆冷水
🔍 基准测试的隐藏变量
Dan Shipper 在 X 上回应：
"基准测试衡量的不仅是模型能力，更是人类专家找到 prompt 让能力显现出来的劳动。"

意思是：高分 = 模型强 + 有人精调出了最能发挥它潜力的 prompt。这两个因素掰不开。
"看到分数别恐慌。那些数字里有一半是 prompt engineer 的功劳。" — Dan Shipper
⚖️ 能力 vs 可调教性
一个真的强但难调的模型 vs 一个没那么强但好上手的模型——benchmark 上后者可能更好看。
但真实场景里，前者一旦找到对的方式，上限高得多。

● 矛盾 05 / 07
分数好看 ≠ 真的好用
📈分数的陷阱
行业已经养成了一种习惯：benchmark 跑分 = 模型实力。
Dan Shipper 提醒的是：分数高度依赖评测 prompt 的设计水平。同一个模型，不同的 prompt → 分差可以很大。
本质是：你在测的是"人+模型"组合，不是模型本身。
🎯行为的说服力
Altman 的回应方式很有意思——他没有贴 benchmark 截图，而是讲了一个故事：丢任务、遛娃、验收。
这是 "Show, don't tell" 的极致版本。
当模型能自主完成一个端到端的工作流，比任何分数都更能说明问题。
